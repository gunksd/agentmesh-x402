问题02

Agent 协作的断点，在付费

今天两个 AI Agent 想互相调用能力，只有两条路可走。两条都不成立。

路径一

人工预先充值订阅

需要人提前开户、充值、配置 API key。Agent 无法自主发现并使用一个它此前不知道的服务—— 清单必须由人预先写好。

路径二

走中心化结算方

引入一个必须被双方信任的中间人，它掌握资金、可以审查交易、并对每一笔抽成。 这与 Agent 自主协作的前提相冲突。

缺的不是算力，也不是模型能力，是一条 Agent 之间可以直接走通的支付通道。

方案03

每个 Agent 都是一个付费 HTTP 端点

编排方需要某项能力时直接发 HTTP 请求。对方返回 402 Payment Required， 编排方本地签名授权，几秒内链上结清，然后拿到数据。

自主发现

从币安 B402 Bazaar 公开目录检索可付费端点。无需 API key，无需预配置清单。

离线签名

EIP-712 本地签名，无 RPC 调用、无需 Gas、无钱包弹窗，耗时几毫秒。

链上结清

BNB Smart Chain 上真实转账，Gas 由 facilitator 代付，收据任何人可核验。

没有中间人持有资金，没有订阅，没有人工审批。

协议04 · x402 v2

一笔支付如何发生

五个步骤，没有一步需要人。

01

发现

查询 B402 Bazaar 公开目录，找到接受 x402 付款的端点。

02

报价

请求资源，收到 402，其中携带金额、代币、网络与 Permit2 spender 地址。

03

签名

本地签署 EIP-712 Permit2 授权，纯密码学运算，不接触链。

04

验证与结算

Facilitator 先离链校验签名，再提交转账并自行承担 Gas。

05

交付

结算确认后释放数据，返回交易哈希供任何人核验。

为什么先验证再结算

校验签名是免费的，能在花掉 Gas 之前挡掉无效授权；而结算是不可逆的一步。 顺序反了会持续为坏签名付费。

创新点 2 / 507
互操作验证

用我们的客户端，付陌生人的账

仅有「发现」说明不了什么——Bazaar 上的挂牌只是元数据。 所以我们真的去调用别人挂上去的端点，解析对方返回的 402。 不花钱，因为 402 本身就是未付款状态的响应。

做这件事时，暴露了我们自己的一个 Bug

那些端点的 body 和 header 内容不一致： body 为向后兼容写的是 x402 v1 / Base 链， 而 PAYMENT-REQUIRED 头里写的是 v2， 并且包含 BNB Smart Chain。

我们的客户端原本只读 body，于是一个本可以支付的端点被判成「不支持的方案」。 改为优先读 header 后，四个被探测端点全部报告兼容—— 而只读 body 的版本曾错误标记出四处网络不匹配和四处版本不匹配。

创新点 3 / 508

持仓量，是价格说不出的那部分

价格只能告诉你「发生了什么」。价格配合持仓量方向，才能说明「是谁在推动」。

价格 持仓量 市场状态 含义
↑ 涨 ↑ 增 多头建仓 新钱进场，四种状态里延续性最强
↓ 跌 ↑ 增 空头建仓 新开空头仓位，而非多头平仓离场
↑ 涨 ↓ 减 空头挤压 空头回补；被迫买盘出清后往往后继无力
↓ 跌 ↓ 减 多头平仓 认赔离场；这类下跌通常会自行衰竭

建仓顺势，挤压与平仓逆势

后两者都是平仓行为——被迫参与者出清后就没人推了。 这个判断在报告的方向权重里占 0.30， 高于 24 小时涨跌的 0.18。

创新点 4 / 509
评分诚实性

评级按「实际可用权重」归一化

信号扫描 Agent 和盘口 Agent 是并行执行的， 所以它永远拿不到盘口失衡数据。

曾经的做法

缺失分项当 0 分

那个分项恒为 0 却仍占 10% 权重，系统性压低每一个评级。 「数据没取到」被当成了「信号很弱」。

现在的做法

分项声明数据是否到位

综合分只除以实际到位的权重。被排除的分项在界面上变暗显示而非隐藏—— 藏掉会让权重看起来加不到 100%。

实测一次运行：6 个分项中 5 个可用，权重 0.90，盘口失衡被排除并标注原因。 评级从受污染的分数回到真实值。

创新点 5 / 510
工程难点

并行结算，在 Serverless 下存活

五个 Agent 由同一个 relayer 地址并发付费。viem 为每笔交易各自去取 pending nonce， 于是并发交易读到同一个值，RPC 只接受其中一笔。

// 进程内：序列化 nonce 分配，保持广播并行 allocateNonce() → 承诺链，读-改-写原子化 // 跨实例：每个 Agent 端点是独立的 serverless 实例， // 兄弟实例的预留不可见 —— 所以碰撞后重试 settle() retry on nonce_collision （抖动退避，最多 5 次）

只有 nonce 冲突会重试。转账 revert 或授权过期每次都会同样失败，重试只是白烧 Gas。

这是只在生产环境出现的故障

本地单个 dev server 共享一份缓存，所以从未复现。 生产环境第一次跑出 3/6，靠新增的诊断端点才定位到。

产出12

网络出售决策，扳机在你手上

报告 Agent 输出可执行的订单参数：方向、挂在价差内侧的限价、按波动率缩放的止损、2:1 的目标位。 然后就停在这里。

限价挂在价差内侧

避免主动成交吃掉盘口分析刚刚赚来的那点边际。

止损跟随实测波动率

固定百分比在快市太窄、在慢市太宽。按日波动率 ×1.5 缩放。

无边际则不出单

方向为中性时不提任何交易。硬凑一笔会与刚付费得到的分析自相矛盾。

为什么停在这里，是设计而非未完成

项目只申请 market_data 与 account 两个只读权限。 真正下单需要 Agent OS 的 trade 权限—— 我们没有申请，因此代码里不存在任何能提交订单的路径。
